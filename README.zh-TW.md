# agentic-graph-notebooks

**將你自己的智能體執行軌跡轉化為圖，並驗證這個圖是否有意義。**

本儲存庫不攜帶任何資料。一切都在*你的*軌跡上、在*你的*機器上執行。

## 為什麼要做這件事

2026 年 7 月，「迴圈 vs 圖」的爭論產生了大量斷言，卻極少有實際測量。這套 notebook 做的是相反的事：一套可複現的協議，針對你自己的智能體回答三個問題。

**1. 圖的形狀是否合適？**

圖只有在「知道某個節點的鄰居能告訴你關於該節點的*特定資訊*」時才有用。有兩種截然相反的失敗方式。太稀疏：大多數節點沒有鄰居，無從分析。太稠密：每個節點幾乎與所有其他節點相連，A 的鄰域與 B 的鄰域相同，毫無區分度。資訊只存在於兩種極端之間。

**2. 圖是否有意義？**

沒有人類命名的統計模式什麼都證明不了。這套 notebook 始終將模式追溯到真實命令，讓你自己判斷——區分可用模式、真實但無價值的模式（`cd` 然後 `ls` 是一個真實模式，也是一個毫無用處的模式）以及純粹的偽影。

**3. 圖是否具有重複性？**

這個問題決定了「程序性記憶」是否有意義。這也是幾乎所有人都會犯錯的地方，因為誠實地回答這個問題需要一條隨機基線。

## 隨機基線，以及為什麼它改變了一切

同一智能體的兩個時間窗口必然共享詞彙：同一台機器、同一套工具、同一個人。因此，原始的持久性分數是**不可解讀的**——而且它會很高，因此看起來很有說服力。

唯一重要的問題是：*超越了偶然性嗎？*

這套 notebook 將相同的動作在相同的窗口間重新打亂二十次並進行比較。在驅動這項工作的語料庫上，有一項鄰域持久性度量達到了中位數 **1.000**——一個驚人的結果，直到隨機基線也回傳了 **1.000**。動作詞彙實在太窄，根本無法產生變化。

沒有這個對照，這個數字本會被當作一項發現發表出去。

## 使用方法

notebook 需要 JSONL 格式的會話檔案——每行一個事件，包含 `toolCall` 區塊。OpenClaw 的格式可以直接使用：

```python
from agentgraph import build_hyperedges, metrics

edges = build_hyperedges("~/.openclaw/agents/*/sessions/*.jsonl")
print(metrics(edges))
```

```
N=465 · edges=4183 · density=0.0388 · mean degree=18.0 · entropy=7.942
→ INFORMATIVE REGIME — neighbourhoods carry information
```

如需適配其他智能體格式，只需修改 `agentgraph/extract.py` 中的 `iter_tool_calls()`，這是你唯一需要改動的入口。

| Notebook | 問題 |
|---|---|
| `01-extract` | 你的軌跡裡有什麼？工具分布、shell 佔比 |
| `02-granularity` | 在哪種粒度下圖不再退化？ |
| `03-motifs` | 你的模式有名字嗎？ |
| `04-stability` | 你的例程是否超越偶然性地重複出現？ |

## 一個比看起來更重要的解析細節

寫 shell 的智能體產生的不是*動作*，而是*程式*。粗略來看，每五條複合命令中約有四條包含 `&&`、`;`、`|` 或換行符。這些運算子正是模型自己寫下的分界——我們就在這些地方分割。

用正則表達式樸素地分割是一個陷阱：它同樣會在引號內部的字串中切割。`grep -E 'a|b|c'` 會變成三條「命令」，每個片段都會產生一個幽靈原子。在一個真實的 2449 條命令的語料庫上，這一個 bug 製造了 **728 個不存在的原子——佔詞彙量的 47%**（`awk.print1`、`awk.print2`……）。

`split_segments()` 使用帶 `punctuation_chars` 的 `shlex`，它能正確處理引號。如果你要改寫這段程式碼，請保留這一屬性。

內聯 Python 則使用真正的 AST 而非正則表達式——這是相對於 shell 的決定性優勢，shell 只能依靠啟發式方法處理。

## 兩條警告

**你的軌跡包含真實的金鑰。** 這不是偶然的，而是系統性的：Bearer token、API 金鑰、環境變數明文出現。`mask_secrets()` 過濾了常見格式並應用於所有模式輸出，但這只是降低風險，並不能消除風險。**在分享任何輸出前，請務必人工審閱。**

**notebook 會標記但無法為你修復的兩個方法論陷阱：**

- *會話自相關*——同一會話內的命令必然彼此相似。如果單一會話主導了某個窗口，你所測量的「穩定性」不過是該會話的內部一致性。`describe_windows()` 在佔比超過 40% 時會發出警告。
- *智能體混合*——如果你的時間窗口對應不同的智能體，你測量的是身份差異，而非時間漂移。在執行穩定性分析前，請先過濾到單一智能體。

## 本協議不做什麼

它測量圖的**形狀**和其模式的**重複性**。它不驗證任何下游任務：形狀良好的圖並不能證明它能改善預測、路由決策或推薦效果。必要條件，非充分條件。

它描述的是智能體*做了什麼*，而不是*何時觸發*它或需要檢查哪些前提條件。這就是圖與可複現程序之間的邊界。
