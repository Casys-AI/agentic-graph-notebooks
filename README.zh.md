# agentic-graph-notebooks

**将你自己的智能体执行轨迹转化为图，并验证这个图是否有意义。**

本仓库不携带任何数据。一切都在*你的*轨迹上、在*你的*机器上运行。

## 为什么要做这件事

2026 年 7 月，"循环 vs 图"的争论产生了大量断言，却极少有实际测量。这套 notebook 做的是相反的事：一套可复现的协议，针对你自己的智能体回答三个问题。

**1. 图的形状是否合适？**

图只有在"知道某个节点的邻居能告诉你关于该节点的*特定信息*"时才有用。有两种截然相反的失败方式。太稀疏：大多数节点没有邻居，无从分析。太稠密：每个节点几乎与所有其他节点相连，A 的邻域与 B 的邻域相同，毫无区分度。信息只存在于两种极端之间。

**2. 图是否有意义？**

没有人类命名的统计模式什么都证明不了。这套 notebook 始终将模式追溯到真实命令，让你自己判断——区分可用模式、真实但无价值的模式（`cd` 然后 `ls` 是一个真实模式，也是一个毫无用处的模式）以及纯粹的伪影。

**3. 图是否具有重复性？**

这个问题决定了"程序性记忆"是否有意义。这也是几乎所有人都会犯错的地方，因为诚实地回答这个问题需要一条随机基线。

## 随机基线，以及为什么它改变了一切

同一智能体的两个时间窗口必然共享词汇：同一台机器、同一套工具、同一个人。因此，原始的持久性分数是**不可解读的**——而且它会很高，因此看起来很有说服力。

唯一重要的问题是：*超越了偶然性吗？*

这套 notebook 将相同的动作在相同的窗口间重新打乱二十次并进行比较。在驱动这项工作的语料库上，有一项邻域持久性度量达到了中位数 **1.000**——一个惊人的结果，直到随机基线也返回了 **1.000**。动作词汇实在太窄，根本无法产生变化。

没有这个对照，这个数字本会被当作一项发现发表出去。

## 使用方法

notebook 需要 JSONL 格式的会话文件——每行一个事件，包含 `toolCall` 块。OpenClaw 的格式可以直接使用：

```python
from agentgraph import build_hyperedges, metrics

edges = build_hyperedges("~/.openclaw/agents/*/sessions/*.jsonl")
print(metrics(edges))
```

```
# （实际数值取决于你的语料库）
N=<节点数> · edges=<边数> · density=<密度> · mean degree=<平均度> · entropy=<熵>
→ INFORMATIVE REGIME — neighbourhoods carry information
```

如需适配其他智能体格式，只需修改 `agentgraph/extract.py` 中的 `iter_tool_calls()`，这是你唯一需要改动的入口。

| Notebook | 问题 |
|---|---|
| `01-extract` | 你的轨迹里有什么？工具分布、shell 占比 |
| `02-granularity` | 在哪种粒度下图不再退化？ |
| `03-motifs` | 你的模式有名字吗？ |
| `04-stability` | 你的例程是否超越偶然性地重复出现？ |
| `05-loops` | 有多少命令包含显式循环——其中有多少对图不可见？ |
| `06-condensation` | SCC 凝聚：图中的反馈有多局部？ |
| `07-repair` | RE-PAIR 语法：重复子序列及其组合深度 |
| `08-read-budget` | 读取预算：前一个动作是否能预测 `head -n N`？ |

## 一个比看起来更重要的解析细节

写 shell 的智能体生产的不是*动作*，而是*程序*。粗略来看，每五条复合命令中约有四条包含 `&&`、`;`、`|` 或换行符。这些操作符正是模型自己写下的分界——我们就在这些地方分割。

用正则表达式朴素地分割是一个陷阱：它同样会在引号内部的字符串中切割。`grep -E 'a|b|c'` 会变成三条"命令"，每个片段都会产生一个幽灵原子（`awk.print1`、`awk.print2`……），背后根本没有真实命令。在真实语料库上，这一个 bug 会凭空制造出相当大比例的虚假词汇。

`split_segments()` 使用带 `punctuation_chars` 的 `shlex`，它能正确处理引号。如果你要改写这段代码，请保留这一属性。

内联 Python 则使用真正的 AST 而非正则表达式——这是相对于 shell 的决定性优势，shell 只能依靠启发式方法处理。

## 两条警告

**你的轨迹包含真实的密钥。** 这不是偶然的，而是系统性的：Bearer token、API 密钥、环境变量明文出现。`mask_secrets()` 过滤了常见格式并应用于所有模式输出，但这只是降低风险，并不能消除风险。**在分享任何输出前，请务必人工审阅。**

**notebook 会标记但无法为你修复的两个方法论陷阱：**

- *会话自相关*——同一会话内的命令必然彼此相似。如果单一会话主导了某个窗口，你所测量的"稳定性"不过是该会话的内部一致性。`describe_windows()` 在占比超过 40% 时会发出警告。
- *智能体混合*——如果你的时间窗口对应不同的智能体，你测量的是身份差异，而非时间漂移。在运行稳定性分析前，请先过滤到单一智能体。

## 本协议不做什么

它测量图的**形状**和其模式的**重复性**。它不验证任何下游任务：形状良好的图并不能证明它能改善预测、路由决策或推荐效果。必要条件，非充分条件。

它描述的是智能体*做了什么*，而不是*何时触发*它或需要检查哪些前提条件。这就是图与可复现程序之间的边界。
